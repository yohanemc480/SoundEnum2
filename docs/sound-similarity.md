# CLAPによる類似音・タグ検索

Pythonで検索用データを生成し、Web側の「類似音・タグ」タブで使用します。ブラウザではモデルを実行しません。

## 現在の検証状態

- 検索画面、Workerによる類似度計算、複合検索、候補を指定した試聴を実装。
- 26.3の1,991イベント・4,941音声の参照とファイルハッシュを検証済み。
- PythonとJavaScriptの自動テストを追加。既存試聴と検索データで、全1,991イベントのピッチ・音量が一致することも確認。
- 依存ライブラリとモデルの導入、全4,941音声のCLAP解析、1,984件の再生可能イベント向けデータ生成を完了。候補が空の7イベントは検索対象外。
- 生成済みデータをWebローダー・Workerに渡した結合検証が成功。実ブラウザの画面操作・音声出力は、確認用サーバーへの接続制限で未確認。
- 自動タグは9種類。閾値0.3は仮設定であり、精度検証後にタグごとに調整が必要です。

## 導入と生成

リポジトリルートで、PyTorchに対応したPythonを使って実行します。

```powershell
python -m venv .venv
python -m pip --python .venv/Scripts/python.exe install -r tools/requirements-clap.txt

# モデルや追加ライブラリ不要のデータ整合性確認
python tools/build_similarity.py 26.3 --validate-only

# モデル取得と少数音声での推論確認（通常画面には反映しない）
.venv/Scripts/python.exe tools/build_similarity.py 26.3 --limit 3

# 全件生成。成功すると検索画面から読み込める
.venv/Scripts/python.exe tools/build_similarity.py 26.3
```

Windows / Python 3.14.2で動作した依存バージョンは`tools/requirements-clap-lock.txt`に記録しています。同じ環境を再現する場合は、上のインストールコマンドのrequirementsファイルをこのlockファイルに置き換えてください。

初回はHugging Faceから`laion/clap-htsat-unfused`を取得します。パッケージ・モデルの取得にはネットワーク接続が必要です。CPUでも動作する設計ですが、全件生成には時間がかかります。CUDAが利用できる場合はGPUを使用します。

pipが`No matching distribution found`を表示した場合、それだけではPython非対応と断定できません。取得先への接続・名前解決と、使用するPythonに対応する配布ファイルの有無を切り分けてください。

## 入出力と再実行

入力は`resource/{version}/sounds.json`、`resource/{version}/hash.json`、`resource/durations.json`、`resource/audio/`です。

- `.cache/clap/`：モデルと音声ベクトル。モデルrevision・前処理・ライブラリバージョン・実行デバイスで識別。破損したベクトルは再生成。
- `resource/{version}/index.json`：イベント、音声、タグ、生成条件。
- 同じディレクトリの`vectors.bin`：little-endian Float32の正規化ベクトル。
- `--limit`では`resource/{version}/index.sample.json`と`vectors.sample.bin`だけを更新。少数サンプルを通常画面で全件データとして使わない。

モデルの既定revisionは動作確認済みの`8fa0f1c6d0433df6e97c127f64b2a1d6c0dcda8a`に固定しています。別の版を使う場合は`--revision`で指定します。取得済みモデルだけで実行する場合は`--offline`を追加してください。依存バージョンもmetadataに記録されます。中断後は同じ条件で再実行すると生成済み音声ベクトルを再利用します。Web公開時は`index.json`と`vectors.bin`を一緒に更新してください。ベクトルのSHA-256が索引と一致しない場合は読み込みを拒否します。切り替え用マニフェストと世代フォルダは使用しません。

ベクトルは4,941音声×512次元なら約9.65MiBです。検索タブで遅延ロードし、検索計算をWeb Workerに分離します。上位20件の事前リストを絞り込む方式ではなく、条件に一致するすべての候補を採点します。

## 検索仕様

再生時間の専用タブは削除し、時間条件は「類似音・タグ」に集約しています。durations JSONと生成処理は、この複合検索のデータ生成に必要なため維持します。

- 基準IDが空ならタグ・名前・時間検索。基準IDを入れると類似度順。
- 複数タグは同一音声候補でのAND条件。タグなしでは全件対象。タグの選択肢は常にすべて表示。
- 時間条件はイベント内の全候補が範囲内に入る条件。
- ID間の類似度は、条件に一致する候補と基準IDの候補との最大コサイン類似度。
- 基準ID自身は除外。同じ音源を共有する別IDは「同一音源」と表示。
- 結果のタグは、試聴対象になった候補のタグをバッジで表示。未付与の場合は「タグなし」と表示。
- 複数候補があるIDでは行内の「候補 N 音」を押すと、一覧の高さを変えずにポップオーバーを開き、、全候補の音声名・ピッチ・タグを確認できる。各候補をクリックするとその音を試聴。
- 結果クリックで一致候補を固定して試聴。ただし生成コマンドと履歴再生はID単位なので、候補はランダム。
- スコアは確率ではなく、ピッチや音量変更を反映しない原音ベースの値。

## タグの調整

`tools/sound-tags.json`にタグID、`Text.js`の表示キー、英語説明文、閾値を定義します。UIの英語対応は不要です。同じCLAPモデルのテキスト特徴を正規化・平均し、音声との類似度で複数タグを付けます。該当なしも許容します。

`tools/sound-tag-overrides.json`で音声ハッシュごとに`add`と`remove`配列を指定できます。除外は自動判定に優先します。未定義タグ、追加・除外の重複はエラーです。タグ変更後は全件生成を再実行しますが、音声ベクトルは再利用できます。

10秒を超える音声は全区間を解析して長さで重み付け平均するため、細かな時間変化は平均化されます。タグ精度と類似順位は試聴評価が必要です。自由文検索、タグ編集UI、OR・除外条件は未実装です。

## テスト

```powershell
python -m unittest discover -s tools -p test_sound_search.py
node --test tools/test_sound_search.mjs

# 全件生成後、Webローダー・Workerで実データを検証
node tools/verify_search_data.mjs
```

結合検証では通信の代わりにファイルを読み、実際の検索ローダー・Workerに渡します。タグごとの一致件数、候補の音源参照、既存試聴との設定一致、類似度の並び順、データ容量と処理時間を確認します。ブラウザの描画・音声出力そのものの検証とは別です。

## 全件生成後の検証結果（2026-11-08）

- 音声ベクトル: 4,941件、512次元、10,119,168バイト（約9.65MiB）。
- キャッシュから再生成して世代ID（索引内容とベクトルのハッシュ）が一致することを確認。自動テストはPython 3件・JavaScript 8件が成功。
- 再生可能イベント: 1,984件。各候補の音源ハッシュ、ピッチ・音量、タグの参照整合性を確認。
- Node.js上で実ローダーとWorkerを使った読み込み: 約68ms。HTTP転送時間・ブラウザ描画時間は含まない。
- 代表6音を基準にした類似検索: 約9〜25ms。同一音源の別IDはスコア約1で返り、基準ID自身は除外。
- 順位の例: 水の環境音に対して泳ぐ音、金床の着地音に対して金床の破壊・使用音や鉄扉を叩く音が上位。これはIDによる結果確認であり、試聴による精度評価は未実施。
