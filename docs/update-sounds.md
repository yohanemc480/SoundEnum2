# サウンド情報の更新

## 不要なバージョンの削除

リポジトリルートで削除予定のファイル・件数・容量を確認できます（通信や追加ライブラリは不要）。

```powershell
python tools/remove_sounds.py 26.2
```

実際に削除する場合は `--apply` を指定します。

```powershell
python tools/remove_sounds.py 26.2 --apply
```

複数版は空白区切りでまとめて指定できます。重複した指定は一つにまとめます。

```powershell
python tools/remove_sounds.py 26.2 26.1
python tools/remove_sounds.py 26.2 26.1 --apply
```

削除対象全版の音声ハッシュの和集合から、残す全バージョンのハッシュの和集合を引き、対象版群だけが使う音声を削除します。版ごとに削除を繰り返さず、各参照表の読み込みと共有JSON・バージョン一覧の更新はそれぞれ一度だけ行います。削除対象同士で共有する音声も、残す版から参照されていなければ削除します。未登録でも `audio-file-hashes.json` がある版の音声は保護します。

- `resource/<version>/` 内のJSON・検索用バイナリとディレクトリを削除します。
- 専用の `resource/audio/<hash>.ogg` と、共有の再生時間・波形JSON内の対応項目を削除します。
- `available-versions.json` から対象版を除き、残りの順序を維持します。
- 対象版と無関係な音声やCLAP推論キャッシュは削除しません。

参照表が欠落・不正な場合や利用可能な版が一つも残らない指定の場合は、変更前に停止します。更新・生成・別の削除処理と同時実行しないでください。一覧から先に対象版を除外します。音声・共有JSONの処理中に失敗した場合は同じコマンドで再実行できます。最後の版ディレクトリの削除中に失敗した場合は、削除済みの版を引数から外し、参照表が残っている版を再指定してください。ファイル単位で処理するため、操作全体の自動ロールバックはありません。

## 取得・生成

リポジトリのルートで実行します（Python 3、インターネット接続が必要）。

```powershell
.venv/Scripts/python.exe tools/update_sounds.py 26.3
```

指定したバージョンの情報をMojangから取得し、`resource/<バージョン>/audio-file-hashes.json` と `resource/<バージョン>/sound-events.json` に保存します。
音声も `resource/audio/<ハッシュ>.ogg` に保存し、再生時間・波形・類似音／タグ検索用の`audio-tags.json`と`audio-embeddings.bin`まで生成した後に `resource/available-versions.json`へバージョンを追加します。
過去のファイルは残し、同名ファイルの内容が異なる場合は上書きせずエラーにします。

音声は保存済みの正常なファイルを再利用し、未取得・破損分だけを最大4件並列で取得します。進捗はファイル数ベースのゲージを同じ行に更新し、個別のハッシュは表示しません。途中で失敗しても再実行できます。
初回は26.3で約377 MB・4,961音声の取得が必要です。JSON取得の4リクエストに加え、必要な音声ごとに1リクエスト発生します。

ローカル再生の前にこのコマンドを実行し、公開時は `resource/audio/` も配置してください。再生時にMojangへアクセスするフォールバックはありません。

再生時間もOGGから集計し、`resource/audio-durations.json` に保存します。保存済み音声だけから再集計する場合（通信なし）：

```powershell
python tools/build_durations.py
```

バージョン固有のJSONと検索データは `resource/<バージョン>/` にまとめます。現在保持するバージョンは26.3のみです。音声はバージョン間で共有するため `resource/audio/` に保持します。

audio-file-hashes.jsonは音声パス（minecraft/sounds/～.ogg）をキー、SHA-1文字列を値とする対応表です。音声以外の情報やサイズは保存しません。ダウンロード時のサイズ・ハッシュ検証には、取得した公式アセット一覧をメモリ上で使用します。sound-events.jsonは公式データの候補音をすべてオブジェクト形式に統一して保存します。文字列の候補はnameだけを持つオブジェクトに変換し、既存の属性・既定値の省略・type: eventによる参照は維持します。

波形は`resource/audio-waveform-peaks.json`へ事前生成します。音声ハッシュごとに最大256区間の絶対振幅ピークを0〜255の整数で保存し、短冊と試聴欄で共用します。ブラウザでは波形用の音声取得・デコードは行いません。更新スクリプトにもnumpy・soundfileが必要です（既存のCLAP用仮想環境を利用できます）。

波形のみ再生成する場合：

```powershell
.venv/Scripts/python.exe tools/build_waveforms.py 26.3
```

再生時間と波形は音声ハッシュをキーとする全バージョン共通データです。生成時は既存の有効な値を再利用し、未登録・不正な値だけを生成します。別バージョンの値は削除しません。波形の仕様が変わる場合は既存ファイルを明示的に再生成してください。

バージョン引数は必須です。最新リリースの自動選択は行いません。公式一覧に存在するバージョンを指定してください。検索データ生成に失敗した場合、バージョン一覧は変更しません。取得・生成済みのデータは残るため、同じコマンドで再実行できます。

検索データ生成には`tools/requirements-clap.txt`の依存ライブラリが必要です。初回はCLAPモデルを取得し、音声を解析するため時間がかかります。再実行では既存の音声ベクトルキャッシュを再利用します。詳しくは[類似音・タグ検索](sound-similarity.md)を参照してください。

画面上部のバージョン選択は`available-versions.json`を読み込みます。生成成功後に公式のリリース日時で新しい順に一覧を並べ直し、URLで指定がなければ最新の生成済み版を表示します。古い版を追加しても初期表示は最新のままです。同じ版の再生成で選択肢は重複しません。切り替え時は`?version=26.3`のようにURLを更新してページを再読み込みし、検索条件・試聴・履歴を初期化します。未登録の版がURLに指定された場合は先頭の版を表示します。公開時は生成済みリソースと一覧を合わせて配置してください。
